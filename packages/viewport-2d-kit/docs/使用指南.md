# 使用指南

## 1. 当前推荐路线（2026-08-26 起，方案 B 定稿）

**唯一渲染内核 = pixi.js**（对齐 V3D = three.js 内核 + 薄壳的架构）：

1. **所有场景（game / map / lite）统一使用 pixi 内核** —— `viewport-2d-kit/pixi` 的 `PixiViewport` / `PixiViewportCanvas`（Vue）或 `viewport-2d-kit/react-pixi` 的 `PixiViewportReact`（React）。渲染内核为 `pixi.js`，相机/坐标/交互复用 core 纯函数。
2. **放进 main-ui = 薄连接器** —— `viewport-2d-kit/main-ui` 的 `ViewportMainUiEditor`：内部挂载 pixi 内核，只提供标签页窗口外观与注册。
3. 历史兼容层（**不建议新增业务依赖**，仅存量迁移期使用）：
   - `Viewport2D` / `Viewport2DCanvas`（自研 CSS transform + slot）
   - `ViewportLite` / `ViewportModeHost`（react-infinite-viewer）
   - 第三方 `pixi-viewport`（`listLegacyViewportEngines()` 可查）

## 2. 快速开始

1. 安装依赖：`pnpm install`
2. 本地开发构建：`pnpm dev`
3. 类型检查：`pnpm typecheck`

## 3. 入口选择

1. **pixi 渲染内核**：`viewport-2d-kit/pixi`（`PixiViewport` / `PixiViewportCanvas`）—— 唯一渲染内核，**首选**
2. **React 薄封装**：`viewport-2d-kit/react-pixi`（`PixiViewportReact`）
3. **main-ui 薄连接器**：`viewport-2d-kit/main-ui`（`ViewportMainUiEditor` + 注册函数）
4. 核心数学：`viewport-2d-kit/core`（与框架无关，内核复用）
5. 历史兼容层：`viewport-2d-kit/vue`、`viewport-2d-kit/modes`、`viewport-2d-kit/react-legacy`、`viewport-2d-kit/ui`

## 4. 典型用法

### 4.1 轻量场景（历史兼容：react-infinite-viewer，新项目走 pixi 内核）

```ts
import { ViewportLite } from 'viewport-2d-kit';

<ViewportLite
  viewBox={{ x: 0, y: 0, width: 2000, height: 1200 }}
  minScale={0.25}
  maxScale={8}
/>;
```

> 提示：新项目请使用 `PixiViewportCanvas`（Vue）或 `PixiViewportReact`（React）。

### 4.2 按模式自动选择（历史兼容：ViewportModeHost，新项目直接选内核入口）

```ts
import { ViewportModeHost } from 'viewport-2d-kit';

<ViewportModeHost
  mode="lite"
  liteProps={{ viewBox: { x: 0, y: 0, width: 1000, height: 800 } }}
/>;
```

### 4.3 查询引擎映射

```ts
import { resolveViewportEngine, listLegacyViewportEngines } from 'viewport-2d-kit';

const descriptor = resolveViewportEngine('map');
// descriptor.engine === 'pixi'  （唯一内核，方案 B）

// 历史兼容引擎（不再推荐）：
listLegacyViewportEngines();
// [{ mode: 'game', engine: 'pixi-viewport', legacy: true }, ...]
```

### 4.4 pixi 渲染内核（推荐 · game/map 场景）

Vue 组件 `PixiViewportCanvas` 内部挂载 `PIXI.Application`，通过 `@ready` 事件把
`PixiViewport` 交给调用方；调用方拿到 `world` 容器后往里加**世界坐标**的
Graphics/Sprite，相机由组件唯一管理（平移拖拽 / 滚轮锚点缩放）。

```ts
<script setup lang="ts">
import { PixiViewportCanvas, type PixiViewport } from 'viewport-2d-kit/pixi';
import { Graphics } from 'pixi.js';

const VIEW_BOX = { x: 0, y: 0, width: 900, height: 620 };

function onReady(vp: PixiViewport): void {
  // 世界容器：相机已应用（scale/pan），业务只加世界坐标内容
  const g = new Graphics();
  g.circle(100, 100, 20).fill(0x2563eb);
  vp.world.addChild(g);
}
</script>

<template>
  <PixiViewportCanvas :view-box="VIEW_BOX" :padding-px="20" @ready="onReady" />
</template>
```

要点：

1. `viewBox`：世界范围（用于初始 fit）。
2. `@ready`：pixi 内核就绪后回调，参数是 `PixiViewport`（含 `app` / `world` / `getCamera` / `screenToWorld` / `fitToBounds`）。
3. `@camera-change`：相机变化（scale/pan），用于同步外部状态（如小地图、缩放百分比）。
4. 点击/右键坐标换算用 `vp.screenToWorld({ x, y })`（`x/y` 为相对 canvas 的 CSS 像素）。
5. `pixi.js` 是 peerDependency，业务侧需自行安装。

### 4.5 放进 main-ui（薄连接器）

```ts
import { registerViewportMainUiEditor, ViewportMainUiEditor } from 'viewport-2d-kit/main-ui';

// 方式 A：一键注册（descriptor + renderer）
registerViewportMainUiEditor(runtime, {
  kind: 'viewport-foundation',
  title: 'Viewport foundation',
  rendererKey: 'viewport-foundation-editor',
  allowedWorkspaceIds: ['workspace-demo'],
});

// 方式 B：仅注册 renderer，descriptor 由宿主自定义
runtime.vue.registerEditorRenderer('viewport-foundation-editor', ViewportMainUiEditor);
```

薄连接器内部挂载 `PixiViewportCanvas`（pixi 内核），payload 的 `nodes` / `edges`
以 Graphics 绘制进 world 容器——连接器不承载渲染实现。

### 4.6 React 宿主使用 pixi 内核

```tsx
import { PixiViewportReact } from 'viewport-2d-kit/react-pixi';

<PixiViewportReact
  viewBox={{ x: 0, y: 0, width: 900, height: 620 }}
  onReady={(viewport) => {
    viewport.world.addChild(new Graphics().rect(0, 0, 200, 120).fill(0xdcfce7));
  }}
  onZoomPercentChange={(pct) => setZoom(pct)}
/>
```

### 4.7 Vue 宿主编辑器壳（历史兼容层）

```ts
import { Viewport2D, ViewportBusinessCanvasShell, useViewportHostBridge } from 'viewport-2d-kit/vue';
```

推荐场景：

1. 业务仓库已有自己的 Cell/Edge/Inspector 状态机。
2. 只想把“布局壳 + viewport 桥接”收口到基础包。
3. 希望在多个宿主项目间复用相同的画布编辑器骨架。

## 5. 本地联调（file 依赖）

1. 在消费项目 `package.json` 添加：`"viewport-2d-kit": "file:../viewport-2d-kit"`
2. 在工具包项目执行 `pnpm dev` 保持 `dist/` 持续更新。
3. 在消费项目执行 `pnpm install` 后启动自身开发服务器。

## 6. 常见问题

1. 找不到模块或类型：确认 `dist/` 已生成并保持更新（`viewport-2d-kit/pixi`、`viewport-2d-kit/react-pixi`、`viewport-2d-kit/main-ui` 子路径需 `pnpm build` 生成对应 `dist`）。
2. 使用 `./pixi` 入口时报 `pixi.js` 缺失：pixi 是 peerDependency，业务侧需 `pnpm add pixi.js`。
3. React 重复实例：确保消费项目安装了与 peer 兼容的 `react`。
4. 使用 `ui` 入口时报依赖缺失：按需安装 Radix 相关包（历史兼容层）。
5. 需要渲染内容：直接向 `PixiViewport.world` 添加世界坐标 Graphics/Sprite（内核唯一管理相机）。
6. 旧的 `renderPixiMode` 占位注入已废弃：统一走 pixi 内核。

## 7. 迁移建议（方案 B 定稿后）

1. **新页面/新项目一律使用 pixi 内核**（`viewport-2d-kit/pixi`）或薄连接器（`viewport-2d-kit/main-ui`）。
2. 存量 `Viewport2D` / `Viewport2DCanvas`（CSS transform）页面：逐页迁移到 `PixiViewportCanvas`，把业务内容从 slot 改为向 `world` 容器添加 Graphics/Sprite。
3. 存量 `ViewportLite` / `ViewportModeHost`（react-infinite-viewer）页面：迁移到 `PixiViewportReact` 或 Vue 的 `PixiViewportCanvas`。
4. 迁移过程中保持相机语义一致（`getCamera` / `setCamera` / `fitToBounds` / `screenToWorld` / `worldToScreen`）。
5. 已接入 main-ui 的宿主：`ViewportMainUiEditor` 已切换为 pixi 内核，payload 契约不变（`viewBox` / `minScale` / `maxScale` / `paddingPx` / `nodes` / `edges`），只需更新 `viewport-2d-kit` 依赖版本。
