# guide-viewport-3d-kit-开发者指南-20260311-001

## 1. 指南目标

本文档面向参与工具包开发与维护的开发者，提供项目结构、模块职责、关键实现路径、扩展建议与验证流程。

## 2. 技术栈

- 构建工具：Vite 5
- 语言：TypeScript 5
- UI 框架：Vue 3（主结构）+ React（兼容层）
- 3D 引擎：Three.js
- Vue 主实现：Three.js 原生控制器（OrbitControls、TransformControls）
- React 兼容实现：`@react-three/fiber`、`@react-three/drei`

设计约束：

1. Three.js 为底层引擎，框架无关。
2. 输入控制细节沉淀在 Core 层，Vue/React 适配层只保留事件桥接。
3. Vue 主实现中的菜单与小地图壳组件独立化，便于替换和复用。

## 3. 对外导出

`package.json` 中定义的子入口：

- `viewport-3d-kit` -> `src/index.ts`
- `viewport-3d-kit/core` -> `src/lib/core/index.ts`
- `viewport-3d-kit/vue` -> `src/lib/vue/index.ts`
- `viewport-3d-kit/react` -> `src/lib/react/index.ts`
- `viewport-3d-kit/ui` -> `src/lib/ui/index.ts`

维护建议：

- 新增可复用能力时，优先放在 `core` 或 `vue` 子入口。
- 避免在根入口直接暴露低层实现细节。

## 4. 目录结构与职责

- `src/lib/core/`：无 UI 的核心数据与工具函数。
- `src/lib/vue/`：视口 Vue3 组件实现（主路径）。
- `src/lib/react/`：视口与小地图 React 兼容组件实现。
- `src/lib/ui/`：基于 Radix UI 的可选外层交互组件。
- `src/styles/`：示例及组件默认样式。

关键文件：

- `src/lib/vue/viewport3d.vue`：Vue 主视口、状态桥接、Three 控制逻辑。
- `src/lib/vue/components/viewport3d-menu.vue`：Vue 菜单子组件。
- `src/lib/vue/components/viewport3d-mini-map.vue`：Vue 小地图壳子组件。
- `src/lib/react/minimap3d.tsx`：小地图渲染、包围盒计算与相机定位。
- `src/lib/core/scene/scene-state.ts`：`ViewportEntity`、演示数据、场景边界计算。
- `src/lib/core/camera/camera-state.ts`：相机状态、序列化、场景聚焦与缩放控制能力。
- `src/lib/core/viewport/mode-state.ts`：工作模式、显示模式、交互预设核心契约。
- `src/lib/core/viewport/input-controller.ts`：输入判定、快捷键映射、鼠标绑定、UE 观察与中键修饰键控制算法。
- `src/lib/ui/viewport3d-toolbar.tsx`：工具栏模式切换与小地图开关。
- `src/lib/ui/viewport3d-context-menu.tsx`：右键菜单行为。

## 5. 核心数据流

`Viewport3D` 内部数据流可以概括为：

1. 读取 `entities`（缺省使用 `createDemoEntities`）。
2. 依据实体生成 `EntityTransformMap` 初始值。
3. 合并受控与非受控状态，得到运行态 `runtimeEntities`。
4. 渲染 mesh，并维护 `meshRefMap` 供 `TransformControls` 绑定。
5. 计算运行态场景包围盒，并生成默认相机状态。
6. 在 `onObjectChange` / `onMouseUp` 时回写变换到 `entityTransforms`。
7. 在 `OrbitControls.onChange` 时同步相机状态到 `onCameraStateChange`。
8. 根据 `workMode/displayMode` 与交互开关，动态映射轨道控制行为与材质呈现。
9. 指针输入、快捷键、上下文菜单屏蔽策略统一通过 `core/viewport/input-controller` 计算。

实现重点：

- 受控模式优先：外部传入状态时，内部仅回调不上锁。
- 非受控兜底：未传入受控状态时，内部 `useState` 负责维护。
- 选中对象变化通过 `SelectedEntityId` 统一处理，可空值安全。

## 6. 关键类型

- `ViewportEntity`：描述场景对象几何与材质属性。
- `SelectedEntityId`：`string | null`，表示当前选中对象。
- `TransformMode`：`'translate' | 'rotate' | 'scale'`。
- `EntityTransformState`：对象实时变换数据。
- `EntityTransformMap`：以对象 `id` 为键的变换字典。
- `ViewportCameraState`：相机位置、目标点、FOV、near/far 平面。
- `ViewportWorkMode`：`runtime | edit`。
- `ViewportDisplayMode`：`wireframe | solid | rendered`。
- `ViewportControlPreset`：`default | modifier-middle`。

## 7. 扩展开发建议

### 7.1 新增对象类型

当前渲染以 `boxGeometry` 为主。若扩展为多几何类型，建议：

- 在 `ViewportEntity` 增加 `kind` 与参数字段。
- 在 `ViewportEntities` 里按 `kind` 分发渲染组件。
- 保持 `id`、`position`、`rotation`、`scale` 的统一变换接口。

### 7.2 业务指令系统

若要支持撤销/重做，建议在宿主层实现命令栈：

- `onEntityTransformsChange` 中记录 patch。
- 通过受控 `entityTransforms` 回放历史状态。

### 7.3 自定义 UI

工具栏和右键菜单可替换：

- 继续使用 `Viewport3D`，仅通过受控 props 控制状态。
- 或拆出 `core + vue`，完全由业务自定义 UI 层。

Vue 子组件策略：

- 默认 `Viewport3D` 已内置 `Viewport3DMenu` 与 `Viewport3DMiniMap`。
- 若业务希望替换默认 UI，可复用导出的两个子组件，或直接用业务组件替代。

### 7.4 相机控制复用

`core/camera` 暴露了相机能力，可用于宿主侧命令系统：

- `resolveCameraStateForBounds`：按场景包围盒生成建议视角。
- `zoomViewportCameraState`：按倍率缩放相机。
- `serializeViewportCameraState` / `deserializeViewportCameraState`：相机状态持久化。

### 7.5 运行与编辑行为建议

1. 运行模式默认开启 Unreal 右键观察导航，优先保证镜头控制。
2. 编辑模式遵循 Blender 术语，优先提供 G/R/S 与显示模式切换。
3. 触控板旋转建议作为可选配置，默认关闭，避免跨设备误触。
4. Vue/React 两侧交互策略变更时，优先改 `core/viewport/input-controller`，再适配到壳层组件。

## 8. 构建与本地验证

常用命令：

```bash
pnpm dev
pnpm build
pnpm preview
pnpm typecheck
```

建议的提交前检查：

- `pnpm build` 必须通过。
- 手动验证：选择对象、切换变换模式、拖拽变换、小地图开关。
- 校对导出入口是否仍可从 `core/react/ui` 正常导入。

## 9. 变更原则

- 最小改动原则：优先在现有类型和数据流内扩展。
- 不保留过时实现：替换后删除旧代码路径，避免双轨维护。
- 保持 API 清晰：公共类型变更需同步更新 README 与文档。

## 10. 文档同步建议

当以下内容变更时，应同步更新文档：

- `Viewport3DProps` 字段新增或语义变化。
- `core` 子入口新增数据模型或工具函数。
- `ui` 子入口新增组件或交互变更。
- 样式类名约定变化（例如 `.vk-*`）。
