# 三维视口的运镜术语与坐标约定

> 面向使用者的科普与操作对照。看完这一篇，你就知道「我正在做的那个动作」
> 在业界叫什么、对应哪个键、以及为什么有些操作被故意做成那样。

## 一、两类「轴」，先分清

谈三维旋转时最容易混淆的，是**世界轴**与**相机轴**是两套东西。

### 1.1 世界轴（World Axes）

世界自己的坐标轴，**不随视角变化**。无论你怎么转相机，世界的 +X 永远指向同一处。

| 轴 | 含义（three.js 约定） | 颜色（业界通例） |
| --- | --- | --- |
| +X | 向右 | **红** |
| +Y | 向上（高度轴） | **绿** |
| +Z | 朝向观察者 | **蓝** |

小地图上那个三色箭头 gizmo 画的就是世界轴 —— 它随相机姿态改变**投影方向与长度**，
因此你能一眼看出「现在是俯视还是侧看」。

### 1.2 相机轴（Camera Axes）

相机自己的三个方向，**随相机姿态变化**：

| 轴 | 含义 | 转动它叫什么 |
| --- | --- | --- |
| 相机 +X | 屏幕向右 | **roll**（横滚） |
| 相机 +Y | 屏幕向上 | **tilt / pitch**（俯仰） |
| 相机 +Z | 屏幕里外（视线轴） | **pan / yaw**（偏航） |

> 注意术语重叠：摄影里的 **pan** 是「相机左右转头（yaw）」，而场景编辑里的
> **pan** 常指「画面平移」。本库在**操作手势**语境下一律把 pan 当作「画面平移」
> （见 §三），与摄影用法不同 —— 这是 DCC 软件的实际惯例。

## 二、运镜（Camera Move）术语对照表

源自电影摄影，3D 软件与游戏引擎沿用同一套词。

| 英文 | 中文 | 动作 | 画面效果 | 本库对应操作 |
| --- | --- | --- | --- | --- |
| **Dolly** | 推拉 | 相机沿视线**前后移动** | 物体变大/变小 | — |
| **Truck** | 横移 | 相机**左右平移** | 画面横向滑移 | `Alt + 中键` 横拖 |
| **Pedestal** | 升降 | 相机**上下平移** | 画面纵向滑移 | `Alt + 中键` 纵拖 |
| **Pan** | 摇 | 相机**原地左右转头**（yaw） | 像摇头环顾 | `Alt + 左键` 横拖 |
| **Tilt** | 俯仰 | 相机**原地上下点头**（pitch） | 像抬头低头 | `Alt + 左键` 纵拖 |
| **Roll** | 横滚 | 相机**绕视线轴自转** | 画面整体歪斜 | **触控板双指扭转** |
| **Zoom** | 变焦 | 改变**焦距**（不移动相机） | 物体变大/变小，透视感变 | `Alt + 右键` / 滚轮 |

> **Dolly 与 Zoom 的区别**是摄影里的经典辨析：Dolly 是**移动相机**（透视关系改变，
> 背景相对大小变化），Zoom 是**改变焦距**（透视关系不变）。
> 本库正交档下两者在画面上等价（正交投影无透视），故统一按「缩放」处理。

### 2.1 你截图里那张「摄像机六动作」

| 截图标注 | 中文 | 说明 |
| --- | --- | --- |
| DOLLY | 推拉 | 沿镜头轴前后走 |
| TRUCK | 横移 | 平行于画面横向走 |
| PEDESTAL | 升降 | 平行于画面纵向走 |
| PAN | 摇 | 原地左右转头 |
| TILT | 俯仰 | 原地上下点头 |
| ROLL | 横滚 | 绕镜头轴自转 |

### 2.2 你截图里那张「三色旋转箭头」

那张图讲的是**绕相机自身轴**转：

| 截图标注 | 中文 | 绕哪根轴 |
| --- | --- | --- |
| X roll | 横滚 | 相机 +X（屏幕横向） |
| Y tilt / pitch | 俯仰 | 相机 +Y（屏幕纵向） |
| Z pan / yaw | 偏航 | 相机 +Z（视线轴） |

> **易混点**：这里是**相机轴**，不是世界轴。世界轴那张图（gizmo）里 Z 是「朝向观察者」，
> 而这里 Z 是「视线方向」—— 两者恰好互为反号，因为相机看向自身 −Z。

## 三、本库的操作手势

### 3.1 鼠标 + 键盘

按住 `Alt`（macOS 上是 `Option`）临时进入视图操作模式，**松开即恢复普通语义**
（左键选择、右键菜单）：

| 组合 | 操作 | 业界对应 |
| --- | --- | --- |
| `Alt + 左键拖拽` | 旋转 | Orbit（轨道旋转） |
| `Alt + 中键拖拽` | 平移 | Truck / Pedestal |
| `Alt + 右键拖拽` | 缩放（锚定光标） | Zoom |

**为什么是「修饰键 + 三键」而不是「中键 + 三个修饰键」**：三个鼠标键物理并排，
左中右 ↔ 旋转/平移/缩放 是连续的空间映射，靠本体感觉即可操作，不必低头确认按对了哪个键。
这是 Blender / Maya 一类 DCC 的通用范式。

### 3.2 触控板

| 手势 | 操作 |
| --- | --- |
| 双指拖动 | 平移 |
| 双指捏合 | 缩放（锚定光标） |
| **双指扭转** | **Roll（绕视线轴自转）** |

**为什么双指扭转映射到 roll**：双指扭转是「绕屏幕法线」的转动，而水平转动是
「绕世界竖直轴」—— 相机一旦倾斜，两者就不再是同一回事，强行映射会让手感随视角漂移。
roll 恰好就是「绕屏幕法线」的自由度，语义严丝合缝。

对照：iPadOS 自带地图把地图拉成地球后，单指拖动是转地球（tilt/pan），
双指扭转就是让地球自转 —— 那就是 roll。

### 3.3 旋转中心

**旋转围绕「按下时光标下的地面点」**，不是画面中心。

> **为什么是「地面点」而不是「光标方向」**：屏幕上的一个像素对应一条**射线**，
> 射线上有无穷多个点，所以「方向」本身定不出中心。但只要视线不水平，
> **射线与地面平面（y = 0）的交点唯一确定** —— 这就是本库取的枢轴。
>
> Blender 的解法是把这件事显式化：它有个可放置的对象叫 **3D Cursor**（红白圈），
> 兼作「新对象生成位置 + 变换枢轴 + 吸附目标」三职。因为它是一个**点**而不是方向，
> 所以连「视线水平」这种退化情形也能表达。

枢轴在**按下时锁定一次**，旋转过程中不重算 —— 否则枢轴会随姿态漂移，表现为「转到一半中心跑了」。

### 3.4 缩放中心

**以光标下的世界点为锚**：缩放前后该点在屏幕上的位置保持不变。

这是 DCC 的通用做法（Blender / Figma / Excalidraw 一致）。锚定画面中心缩放会让人
反复「缩放 → 平移 → 再缩放」，效率极低。

## 四、两种旋转模型：转盘 vs 轨迹球

这两个词对应你提到的「经纬球 vs 棱角球」。

| | 转盘 `turntable` | 轨迹球 `trackball` |
| --- | --- | --- |
| 别名 | 轨道旋转 / Orbit / 经纬球 | 虚拟轨迹球 / Trackball / 棱角球 |
| 转轴 | 固定的世界竖直轴 + 水平轴 | **屏幕空间里、垂直于拖拽方向的任意轴** |
| 极点 | 有（转到顶会卡住） | 无 |
| 拖拽轨迹转弯时 | 坐标系不跟 | **坐标系跟着转** |
| 累积 roll | 不会（地平线永远水平） | 会（久了画面会歪） |
| 代表软件 | **Blender 默认** / Maya / 大多数 DCC | Blender 的 Trackball 选项 / MeshLab / CAD |

### 4.1 怎么选

- **要「不会迷失方向」→ 转盘**。地平线永远水平，适合方形棋盘这类「歪了就难认格」的场景。
- **要「怎么搓都行」→ 轨迹球**。任意方向都能转、没有极点，适合抽象盘面。
- 轨迹球用久了若觉得画面歪，点「**摆正**」清掉累积的自转（对应 Blender 的
  `View > Align View > Top` 一类操作）。

### 4.2 为什么 Blender 默认不给 roll

**roll 会让人迷失方向**。地平线一歪，人对「上」的直觉就失效了。所以业界惯例是：

- **主拖拽不给 roll**（只做转盘旋转）
- **roll 单独提供**（Blender 的 `View > Navigation > Roll`，或拖导航 gizmo 的 roll 环）
- **且配一键复位**

本库把 roll 接到触控板双指扭转，正是「单独提供 + 复位」两条都做到了。

## 五、坐标系：四大类与换算

「坐标系」不是一个选项，而是**两个正交的二选一**：手性（右手/左手）× 向上轴（Y up/Z up）。

| | **Y up** | **Z up** |
| --- | --- | --- |
| **右手** | **three.js** · glTF · OpenGL · SceneKit / RealityKit（苹果） · Maya · Godot | **Blender** · 3ds Max |
| **左手** | Unity · DirectX | **Unreal Engine** |

- **three.js** = 右手 + Y up，相机看向自身 **−Z**
- **Blender** = 右手 + Z up
- **苹果原生 3D**（SceneKit / RealityKit / USDZ / Model I/O）= **右手 + Y up**，与 three.js 同类

### 5.1 换算的两步法

不要背矩阵，记两步，**顺序不可交换**：

1. **先统一手性** —— 源是左手则翻转一个轴（惯例翻 Z）：`(x, y, −z)`
2. **再统一向上轴** —— 源是 Z up 则绕 X 轴 −90°：`(x, y, z) → (x, z, −y)`

| 源 | 第一步 | 第二步 | 到 three.js 的结果 |
| --- | --- | --- | --- |
| 右手 Y up（three） | 无需 | 无需 | `(x, y, z)` |
| 右手 Z up（Blender） | 无需 | `(x, z, −y)` | `(x_b, z_b, −y_b)` |
| 左手 Y up（Unity） | `(x, y, −z)` | 无需 | `(x_u, y_u, −z_u)` |
| 左手 Z up（UE） | `(x, y, −z)` | `(x, z, −y)` | `(x_u, −z_u, −y_u)` |

**手性可以自己验，不必查表**：`X × Y` 等于 `Z` 就是右手。

> 本库统一走右手 + Y up。宿主若数据来自 Blender/UE，用
> `@main-ui/core/rendering` 的 `toThreeAxis(v, KNOWN_SYSTEMS.blender)` 换算即可。

## 六、常见问题

**Q：转到一半画面甩出去了？**
旋转枢轴锁在「按下时的光标位置」。想绕画面中心转，就把光标放到画面中心再按下。

**Q：画面歪了回不来？**
用轨迹球模式时会累积 roll。点「摆正」，或切回转盘模式。

**Q：缩小到很小之后内容不见了？**
这是旧版缺陷（相机被拉进场景内部）。当前版本已修：正交档的相机距离不再随缩放同步缩小。

**Q：为什么 `Alt + 左键` 是旋转，不是选择？**
未按 `Alt` 时左键仍是选择。`Alt` 临时改写三键语义，松开即恢复 —— 这是 DCC 的通用范式。
